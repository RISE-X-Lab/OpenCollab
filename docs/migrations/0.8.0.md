# OpenCollab 0.8.0 migration guide

This guide records the 0.8.0 release transition and the follow-up changes listed
below. Use the [Base and Single2 guide](../single2.md) and
[package guide](../../opencollab/README.md) for the current implementation.

OpenCollab 0.8.0 introduces the Base profile system, makes Single2 the default standalone agent, and removes the legacy Single implementation.

## Breaking changes

### Base replaces Single as the default agent

The default standalone agent is now **Base**, currently mapped to Single2. The legacy Single implementation and its prompt have been removed.

**Before (0.7.x):**
```python
from opencollab import OpenCollab

client = OpenCollab(workspace)
# Used legacy Single by default
result = await client.agent(task)
```

**After (0.8.0+):**
```python
from opencollab import OpenCollab

client = OpenCollab(workspace)
# Now uses Base (currently mapped to Single2)
result = await client.agent(task)
result = await client.agent(task, profile="base")  # Explicit

# Or select Single2 directly
result = await client.agent(task, profile="single2")
result = await client.agent2(task)  # Convenience entry
```

### Profile name resolution changes

The `default` and `single` profile names now resolve to Base instead of the removed Single implementation.

**Migration:**
- `profile="default"` → uses Base (currently Single2)
- `profile="single"` → uses Base (currently Single2)
- `profile="single2"` → uses Single2 explicitly
- `client.agent2(task)` → calls the Single2 convenience entry
- No profile specified → uses Base (currently Single2)

If your code relied on the legacy Single implementation, you must update to Single2 and review its differences:
- Single2 uses a static repair prompt (evaluated on SWE-Mix-80)
- 200 steps by default (vs Single's limits)
- Ordered tool set: `bash`, `file_read`, `file_write`, `apply_patch`, `git_diff`, `grep`
- Bash requires process isolation by default
- Oversized tool results keep both head and tail within 16,000-character context cap

### Explicit token and step limits behavior

With `OPENCOLLAB_UNBOUNDED_LIMITS=true`, explicit `budget` or `max_steps` passed to Base or Single2 remain effective. Omitted limits use the unbounded setting.

**Before (0.7.x):**
```python
# Limits always enforced
result = await client.agent(task, budget=1_000_000)
```

**After (0.8.0+):**
```python
# With OPENCOLLAB_UNBOUNDED_LIMITS=true
result = await client.agent(task, budget=1_000_000)  # Explicit limit honored
result = await client.agent(task)  # Uses unbounded setting
```

This prevents evaluation adapters from having finite allowances silently replaced with profile defaults.

## New features

### Named profile factory registry

A new profile factory registry makes single-agent implementations extensible. The public `opencollab.profiles` module exposes the Base profile mapping.

```python
from opencollab.profiles import BASE_PROFILE, resolve_profile_name

assert BASE_PROFILE == "single2"
assert resolve_profile_name("base") == "single2"
assert resolve_profile_name("default") == "single2"
```

New implementations can be added in `opencollab/bootstrap/agent_profiles.py`. Each factory supplies its prompt, tool resolver, shaper, safety wrapper, and default limits.

### Profile selection in workflows

Workflows can now select the same profile for every role through the public facade.

```python
from opencollab.tools import builtin_tools

async def flow(ctx, inputs):
    tools = builtin_tools("bash", "file_read", "grep")
    return await ctx.agent(inputs["task"], tools=tools, label="coder")

# All roles use Base (currently Single2)
result = await client.workflow(flow, {"task": task}, agent_profile="base")

# Or select Single2 explicitly
result = await client.workflow(flow, {"task": task}, agent_profile="single2")
```

Workflows that omit `agent_profile` retain their role-defined configuration.

### Completed runs record concrete profile name

Result metrics now record the concrete implementation name for configuration and run records.

```python
result = await client.agent(task, profile="base")
assert result.metrics["agent_profile"] == "single2"
```

### Profile tool limits for inspection

`profile_tool_limits()` returns a copy of the tool defaults for inspection.

```python
from opencollab.tools import profile_tool_limits

limits = profile_tool_limits("single2")
print(limits)  # Shows Bash output limits, etc.
```

## Single2 behavior details

Single2 is the Base-mapped implementation in 0.8.0. Key characteristics:

- **Prompt:** Evaluated static repair prompt from SWE-Mix-80 configuration
- **Default steps:** 200 (configurable via `max_steps`)
- **Tools:** `bash`, `file_read`, `file_write`, `apply_patch`, `git_diff`, `grep` (in order)
- **Bash isolation:** Requires process isolation (Docker or similar); local execution needs explicit tool configuration with `headless=False`
- **Tool output limits:** Bash retains up to 10,000 characters per stream; oversized results keep head and tail within 16,000-character context cap
- **Container-root search protection:** Recursive searches rejected at container root, workspace-scoped searches remain available

For deliberate local shell execution:
```python
from opencollab.tools import builtin_tools, profile_tool_limits

tools = builtin_tools(
    "bash", "file_read", "file_write", "apply_patch", "git_diff", "grep",
    headless=False,
    limits=profile_tool_limits("base")
)
result = await client.agent(task, tools=tools)
```

## Test organization changes (0.8.1)

OpenCollab 0.8.1 reorganized tests by behavior area: agents, workflows, tools, runtime, interfaces, and packaging. Test workspaces use temporary or external paths. This does not affect API usage but may affect development workflows.

## Upgrade steps

1. **Install the release being migrated to from its verified Git tag.**
   ```bash
   python -m pip install "opencollab @ git+https://github.com/RISE-X-Lab/OpenCollab.git@v0.8.0"
   ```
   GitHub release wheels provide the other supported installation path.

2. **Review agent profile usage:**
   - If using default agent, it now uses Base/Single2 instead of legacy Single
   - Update any code that explicitly requested `profile="single"` to understand it now resolves to Base/Single2
   - Review Single2 behavior differences (steps, tools, isolation requirements)

3. **Update Bash execution for local workflows:**
   - If running Single2 locally (non-Docker), configure tools with `headless=False`
   - Or ensure Docker environment is available for process isolation

4. **Test with explicit profile selection:**
   ```python
   # Verify Base behavior
   result = await client.agent(task, profile="base")
   
   # Or lock to Single2 explicitly
   result = await client.agent(task, profile="single2")
   ```

5. **Update OpenCollab-Eval if used:**
   - Upgrade to compatible 0.8.x version
   - Verify profile compatibility with evaluation harness

6. **Run your test suite:**
   - Verify agent behavior with new Base/Single2 default
   - Check token/step budget behavior
   - Verify workflow profile selection if used

## Version compatibility

- OpenCollab 0.8.0, 0.8.1, 0.8.2, and 0.8.3 are compatible with OpenCollab-Eval 0.8.x
- All 0.8.x versions use Single2 as the Base mapping

For migration from 0.6.x, see the [0.7.0 migration guide](0.7.0.md) first.
