# OpenCollab 0.7.0 migration guide

OpenCollab 0.7.0 introduces evaluation runtime support, the built-in Duo workflow, and removes the `run_tests` tool in favor of native Bash execution.

## Breaking changes

### Native Bash testing replaces `run_tests`

The built-in `run_tests` tool has been removed. Tests now run through the native Bash tool.

**Before (0.6.x):**
```python
# run_tests tool was available by default
tools = builtin_tools("bash", "file_read", "file_write", "run_tests")
```

**After (0.7.0+):**
```python
# Use Bash for all test execution
tools = builtin_tools("bash", "file_read", "file_write", "apply_patch", "grep", "git_diff")
```

See the [remove-run-tests migration guide](remove-run-tests.md) for detailed transition instructions.

### Duo workflow shell execution requires opt-in

Local Duo shell execution now requires explicit caller opt-in via `allow_unisolated_shell`. The default requires process isolation (Docker or similar).

**Before (0.6.x):**
```python
# Shell execution was unrestricted
result = await client.workflow("duo", {"goal": "Fix the bug"})
```

**After (0.7.0+):**
```python
# Explicit opt-in required for local shell execution
result = await client.workflow(
    "duo",
    {"goal": "Fix the bug", "allow_unisolated_shell": True}
)
```

Container-backed environments can omit this flag and retain the default isolation requirement.

## New features

### Built-in Duo workflow

Duo is now the single installed dual-candidate workflow, available through CLI and SDK without requiring a `workflows/` directory.

```bash
opencollab workflow run duo --workspace /path/to/workspace \
  --args '{"goal":"Complete the task","allow_unisolated_shell":true}'
```

```python
from opencollab import OpenCollab

client = OpenCollab("/path/to/workspace")
result = await client.workflow(
    "duo",
    {
        "goal": "Produce the requested data files and update their configuration.",
        "candidate_evidence_dir": "artifacts/duo-evidence",
        "allow_unisolated_shell": True,
    },
    budget=1_000_000,
    artifacts="artifacts/duo-run",
)
```

The workflow uses task-oriented prompts (revision 4), complete paged candidate evidence, and supports both Git-based and full-environment candidate backends.

### Named workflow discovery

Named SDK workflow calls now discover both installed and caller-defined workflows.

```python
from opencollab.builtin_workflows import duo, get_builtin_workflows

# Use the function directly
result = await client.workflow(duo, args, budget=1_000_000)

# Or get the registry
registry = get_builtin_workflows()  # Returns {"duo": duo}
```

CLI and SDK name lookup combine installed workflows with the workspace's `workflows/` directory or `OPENCOLLAB_WORKFLOWS_DIR`.

### Evaluation runtime support

0.7.0 adds paired evaluation runtime support with:
- Candidate workspace isolation
- Configured unbounded limits via `OPENCOLLAB_UNBOUNDED_LIMITS=true`
- Public model and snapshot inspection
- Durable request lifecycle observations

### Native test evidence observation

New `evidence_tools()` wraps Bash with execution observers that recognize pytest, Go tests, and Django test runners.

```python
from opencollab.tools import evidence_tools

tools = evidence_tools(
    "bash", "file_read", "file_write", "apply_patch", "grep", "git_diff",
    headless=True,
    allow_file_creation=True,
)
candidate = await ctx.candidate_agent(prompt, tools=tools, label="coder")
print(candidate.test_records)
print(candidate.verified_targets)
```

### Public Git patch parser

`opencollab.patches` provides Git diff block and path parsing for workflows and external integrations.

```python
from opencollab.patches import patch_entries, patch_paths, split_patch_blocks

entries = patch_entries(diff_text)
paths = patch_paths(diff_text)
blocks = split_patch_blocks(diff_text)
```

## Bug fixes

- Revoked execution environments now terminate their sessions instead of continuing ineffective tool calls
- Candidate worktrees retain correct environment and cleanup ownership
- Redirected CLI input preserves queued tasks and answers, including pipes, ordinary files, encodings and concurrent questions
- Docker control operations now allow 60 seconds for daemon cleanup

## Upgrade steps

1. Pin and test against `opencollab==0.7.0` or `opencollab==0.7.1`
2. Remove any explicit `run_tests` tool references and update agent prompts to use Bash for testing
3. If using Duo workflow, add `allow_unisolated_shell: true` for local execution or ensure Docker environment is available
4. If using OpenCollab-Eval, upgrade to a compatible 0.7.x version
5. Run your test suite to verify compatibility

## Version compatibility

- OpenCollab 0.7.0 pairs with OpenCollab-Eval 0.7.0
- OpenCollab 0.7.1 contains Duo workflow refinements and is compatible with OpenCollab-Eval 0.7.x

For the next major version, see the [0.8.0 migration guide](0.8.0.md).
