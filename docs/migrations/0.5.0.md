# OpenCollab 0.5.0 migration guide

This guide records the compatibility changes required by the audited lifecycle
and scheduler fixes. The package metadata remains `0.4.1` while the high- and
medium-risk batches are reviewed; the final integration must bump the package
and test metadata to `0.5.0` together.

## Runtime failures are explicit

Callers that previously inferred success from an empty string, a `DONE`-looking
pending row, or a completed coroutine must handle the actual terminal state.

- A delegated child that reaches `STOPPED` or `ERROR` is reported as a failed
  child result; it is never converted to `DONE`.
- `Scheduler.run_turn()` raises `SchedulerTurnError` when the target agent
  terminates unsuccessfully. A scheduler that cannot reach a terminal state
  raises `SchedulerStalledError`.
- Concurrent `Session.run_loop()` and `Session.add_user_message()` calls raise
  `SessionBusyError`. Serialize public turns or coordinate them in the caller.
- `snapshot_session()` requires cloneable, independently forkable runtime
  collaborators and raises `SnapshotSessionError` when that contract cannot be
  satisfied. A shallow copy is not a valid snapshot.

The exception classes are intentionally exposed at their owning boundaries:

```python
from opencollab.application.scheduler import (
    SchedulerStalledError,
    SchedulerTurnError,
)
from opencollab.application.session import SessionBusyError
from opencollab.bootstrap import SnapshotSessionError
```

## Isolation and ownership

`isolation=True` is now a hard requirement. If the selected environment cannot
provide an isolated fork, agent/workflow construction fails with `ValueError`
instead of silently running in a shared environment. Timeouts and cancellation
also leave caller-owned environments under caller control; OpenCollab only
cleans up resources it owns.

## Budget, turn, and delivery semantics

Provider truncation (`finish_reason="length"`) is a controlled stop, not a
successful answer. Token accounting includes structured tool-call payloads,
late provider usage, and the output cap for the current turn. Parallel and
pipeline budget stops propagate to the outer run. Restored sessions replay a
queued external turn exactly once and preserve its answer boundary.

Teammate inbox delivery is bounded by count and bytes, drains appended messages
before shutdown, and deduplicates restored messages. Deferred tool batches are
validated and capped just like the original batch.

## Self-collaboration and workflow contracts

The coder must finish in `DONE` before a reviewer `VERDICT: PASS` can mark a
self-collaboration loop successful. Reviewer `STOPPED` and `ERROR` outcomes are
failures. Workflow tool schemas now enforce declared constraints locally, and
discovery loads modules with normal import semantics so relative imports and
dataclasses remain valid.

## Upgrade checklist

1. Catch the explicit exceptions above at the boundary that owns retry or user
   messaging; do not convert them to a successful empty result.
2. Provide an environment implementing `fork_snapshot()` whenever using
   `isolation=True` or `snapshot_session()`.
3. Treat `STOPPED` and `ERROR` child rows as failed work and decide whether to
   retry or surface the failure.
4. Update integrations that depend on permissive tool/schema inputs to pass
   validated, declared values.
5. When the medium-risk batch lands, follow the additional provider-key,
   configuration strictness, turn wind-down, compaction, and SDK-parameter
   notes added to this file before releasing `0.5.0`.
