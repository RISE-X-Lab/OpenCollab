Topology × Ablation × Clean Architecture

同一内核 两种拓扑 一张干净实验台

Team 与 Workflow 研究不同的协作控制方式；Harness 通过 Ports 替换单一变量做消融。 SDK 不承载这些研究复杂度，它只提供稳定的启动与观测入口。

CONTROL = agent baseline · team topology · workflow topology
TREATMENT = one replaceable Port / Adapter
OBSERVATION = RunResult + trajectory + artifacts

右侧实验台可聚焦 Team 或 Workflow，观察它们如何落到同一个 Session 内核。

RESEARCH PRINCIPLE / 01
让 topology 研究者改变控制图，而不是重写 Agent 内核。
TWO CONTROL REGIMES

Topology research

同一进程，两种控制方式

两种模式都驱动相同的 session.run_loop()。研究者可以把注意力放在 “谁决定下一条边、图如何展开”，而不是模型调用、工具执行和状态机差异。

Team

emergent collaboration topology
  • Graph角色之间允许 spawn / message 的有向权限图。
  • ControllerLLM-supervised Scheduler 根据运行中状态决定委派与通信。
  • DynamicsSessionTable、父子关系、pending events 与消息 inbox 随执行展开。
  • Research星型、层级、角色约束、通信边和动态分工如何影响结果。

Workflow

programmed control topology
  • Graph由 Python 函数显式表达 phase、fan-out、pipeline、merge 与 verify。
  • ControllerWorkflowContext 按作者写下的控制流驱动一次性 Agent Session。
  • Dynamics并发、顺序、预算分配与结束条件可复现、可检查。
  • Research固定协议、并发结构与验证位置如何改变效率和可靠性。

CLEAN ABLATION

Harness research

替换一个 Port，保持核心不动

Harness 位于系统外层，定义实验条件并请求 Bootstrap 装配。依赖只向内指向 application/domain，因此一次消融应替换一个 Adapter，而不是在核心逻辑里插条件分支。

定义 treatment、样本、seed、预算与评价口径。

ABLATION RULE
effect = outcome(adapter B) − outcome(adapter A)
while task · core · regime · budget · evidence policy stay fixed
LLMPort

替换模型或 provider；保持 Session runner、工具和预算规则不动。

ShaperPort

比较上下文压缩策略；保留完整持久化历史和执行语义。

ToolPort

增删工具能力或改变实现；Tool execution use case 保持一致。

EnvironmentPort

切换本地、容器或隔离环境；路径与副作用契约不变。

TracePort / SessionStorePort

改变观测和持久化设施，而不让测量机制进入 domain。

WorktreePoolPort

消融协作隔离策略；Scheduler 仍通过同一资源接口工作。

THIN SDK CONTROL PLANE

Why the SDK is small

SDK 是控制面，不是研究对象

Topology 的复杂度属于 Team / Workflow；消融的复杂度属于 Harness / Ports。 SDK 只需稳定表达“运行哪种 regime”并返回同一种观测结果。

ONE TASK / THREE CONTROL CONDITIONS same observation envelope 
from opencollab import OpenCollab
from study import protocol

oc = OpenCollab(".")
task = "修复目标缺陷并验证"

# 单进程控制基线
baseline = await oc.agent(task)

# LLM-supervised 动态拓扑
emergent = await oc.team(
  task,
  config="configs/team.yaml",
)

# code-driven 程序化拓扑
programmed = await oc.workflow(
  protocol,
  {"task": task},
)
IN
三个 regime 入口

agent 是控制基线；team 与 workflow 是两种研究拓扑。

OUT
一个 RunResult

统一 output、status、tokens、metrics、artifacts，方便 Harness 比较。

DI
实验注入留在 Bootstrap

SDK 不 re-export Scheduler、Session 或所有 Ports，研究自由留在内部边界。

EXPERIMENT METHOD

Research workflow

从问题到可归因结果

架构的最终价值不是“看起来分层”，而是让实验问题能对应到一个明确、可替换的位置。

01

CHOOSE REGIME

固定 agent、team 或 workflow 控制条件。

02

SELECT TREATMENT

只选择一个 Port / Adapter 作为消融变量。

03

HOLD CORE

固定 task、Session FSM、预算与证据策略。

04

RUN HARNESS

Harness 请求 Bootstrap 装配并批量运行实验条件。

05

COMPARE EVIDENCE

比较统一结果、trajectory、tokens 与 artifacts。

研究复杂度留在正确的层，SDK 才能保持简单。 topology → regimes
ablation → ports
invocation → SDK

改变拓扑，替换变量，不要污染内核。
