SDK 0.4 / architecture thesis

门面只有 四个名字 机器仍然完整

OpenCollab 把调用者必须记住的表面，从请求 DTO 图收敛成一个客户端； 超时、清理、持久化与证据校验没有被删掉，而是回到了唯一正确的位置：bootstrap。

  • workflow

收窄认知入口，而不是安全边界。右侧可切换“表层 / 剖面”。

DESIGN PRINCIPLE / 01
精简的是调用者必须记住的东西，不是清理、超时与证据。
CONTRACT APERTURE

Why this refactor

把认知入口收窄

v2 的问题不是功能不够，而是每次调用都要求用户先理解配置、预算、请求和结果四层对象。 0.4 保留能力，删除仪式。

Top-level exports

37→4

日常入口只剩客户端、结果、错误和装饰器；高级协议按需导入。

Frozen DTO fields

63→7

Agent、Team、Workflow 共用一个 RunResult，不再各有一套结果语法。

First-class regimes

2→3

Team 不再是内部特例；agent、team、workflow 成为对称的一等入口。

OWNERSHIP MAP

Architecture

每层只知道它该知道的

关键变化不是把旧 Runtime 换个名字，而是取消 SDK 内部的第二套组装逻辑。 具体类型只在 bootstrap 相遇。

opencollab/__init__.pylazy public aperture

惰性暴露四个公共名字，保持根包冷启动轻量。

不解析配置，不加载 LLM，不组装运行时。

sdk/client.pythin stateful facade

构造时解析一次配置；校验普通参数；把调用委托出去。

不 import concrete adapter，不管理 Session 生命周期。

bootstrap/programmatic.pysingle composition root

组装 Agent、Environment、Tracer、Scheduler；确认资源所有权。

不创造第二套业务状态机，不复制 application 规则。

hardened runtimesagent · team · workflow

执行、取消、清理、持久化，并返回真实 token/session 指标。

不向调用者泄漏三套不同的结果模型。

application → domaininward dependency

用例、端口、调度和纯 FSM 保持独立可测。

不知道 CLI、SDK、LLM provider 或文件系统实现。

OWNED LIFECYCLE

Execution path

小门面，硬生命周期

这七步是真实的先后顺序。只有在工作静默、证据可信后，调用方才拿到 RunResult。

01

VALIDATE

校验 prompt、budget、timeout、路径和 workflow 输入。

02

RESOLVE

复用中央配置，并解析 coding/read 工具预设。

03

CLAIM

原子写入 .opencollab-run，拒绝证据目录复用。

04

COMPOSE

bootstrap 组装具体环境、工具、追踪与执行者。

05

EXECUTE

进入已有 hardened runtime，不另造执行循环。

06

QUIESCE

有界取消、撤销副作用、等待清理和保存任务结束。

07

VERIFY

验证 claim、transcript 或 manifest，再生成结果。

OUTCOME SEMANTICS

One result model

执行失败，不等于基础设施失真

可描述的运行结局返回 RunResult；无法证明资源已经收干净、证据已经落盘时，才抛 RunError。 

RunResult(
  output=...,
  status="completed | stopped | failed",
  reason=...,
  tokens=...,
  artifacts=...,
  error=...,
  metrics=...,
)
completed 正常完成；output 可用，result.ok 为 true。
stopped 超时或预算停止，但终止与清理已得到证明。
failed 模型、workflow 或 team 执行失败；错误作为结果证据保留。
RunError 任务未静默、清理失败或证据不完整；拒绝返回“可信结果”。

HONEST TRADE-OFFS

Deliberate boundaries

保留什么，也明确不保留什么

小 SDK 最怕以兼容为名重新长回两套表面。0.4 是 alpha 阶段的一次有意断代。

继续守住

  • 中央配置解析与凭据优先级
  • 有界取消、环境 revoke / abort / cleanup
  • Agent transcript、Team manifest 与 Workflow evidence
  • 调用方自有 Environment 的清晰所有权
  • application → domain 的向内依赖

有意切掉

  • OpenCollabRuntime 与请求/预算 DTO 图
  • 独立 SDK_API_VERSION；统一跟随 package SemVer
  • 七个旧 sdk.* capability / compatibility 模块
  • Team 自定义 Environment：暂不模糊 scheduler/worktree 所有权
  • 假装外部 OpenCollab-Eval 已迁移；升级前必须单独验证
