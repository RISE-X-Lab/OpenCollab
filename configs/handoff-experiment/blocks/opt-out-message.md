## Either way, the Coder hears from you

The Coder is seated with a budget of its own and nothing yet to act on: until a
message reaches it, it does nothing at all. So one `message_agent` call to the
Coder is part of this run either way. If you are handing the implementation
over, that message is the description of the change. If you are keeping the
implementation, that message says so, so the Coder can stop waiting on a
handoff that is not coming instead of holding a seat open for one.

Which of those two messages you send is yours to decide, on the same grounds as
any other call about a piece of work: what the request actually needs, what is
worth another agent's attention, and what it costs to describe a piece of it
well enough to hand over. The choice between them is yours. Sending one of them
is not.
